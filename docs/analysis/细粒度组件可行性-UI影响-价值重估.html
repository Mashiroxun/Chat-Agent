具体怎么改

// ① 顶部：加一个可选的 components 参数
export function createOrchestrator({ store, memory, sender, sessions, onebot,
  emit, reminders, videoReader, components = {} }) {

// ② 构造时解析一次，缺省回落到原实现
  const systemPromptFor  = components['core.prompt.system']  ?? buildSystemPrompt;
  const userPromptFor    = components['core.prompt.user']    ?? buildUserPrompt;
  const pastStateFor     = components['core.prompt.pastState'] ?? buildPastState;
  const resolveWake      = components['core.wake.resolve']    ?? resolveContextTier;
  const llmComplete      = components['llm.complete']         ?? chatCompletionWithRetry;
  const retryable        = components['core.session.retryable'] ?? isRetryableError;
  const rescueReply      = components['core.reply.rescue']    ?? rescueUnsentReply;
  // ... 其余同理，共 14 行

// ③ 调用点：把直接调用换成变量
  const sys = buildSystemPrompt(ctx);
  const sys = systemPromptFor(ctx);
}

关键点：默认值全部指向原实现，所以不传 components 时行为 100% 不变。这就是"薄注入"——不是重构，是在原有调用链上加一个可选的岔路口。

这一步的真正价值

加完之后，换系统提示词、换上下文选取策略、换模型调用封装、换文本切分规则——全都不用改源码了，写个 overrides 层声明一下就行。

而这些东西恰好是一个魔改项目最频繁要调的地方。你过去两年在 prompt.js（82 KB）和 llm.js（75 KB）里改的每一处，以后都可以变成"一层可开关的覆盖"。

02UI：最大影响是零，前提是别做错一件事

Tier 1 + Tier 2 + 细粒度组件注入，对 UI 的影响是 0

这三次改动全部发生在后端：app.js 的装配块、orchestrator.js 的调用点、新增的 composition/ 目录。不碰 ui/ 下任何一个字节。

你辛苦调出来的 20 个全局脚本、设计 token、明暗主题、玻璃效果、动效，全部原样保留。

唯一会动 UI 的是 console.panels —— 而它正好可以不做

我上一份建议"补 console.panels（300–500 行）拿到加页自由"。在你"必须保留现有 UI"的前提下，这个建议要撤回。

洛版的侧边栏是 ui/index.html 里 6 个硬编码的 <button class="nav-item" data-tab="...">：

补 console.panels 反而会伤到你现有的 UI

要做"数据驱动渲染"，必须把这段静态 HTML 拆掉、改成 14-chrome.js 动态生成。而 14-chrome.js 有 2,140 行，里面除了 tab 切换还有主题切换、玻璃效果、快捷键、窗口控制。

为了一点点"加页不用改 HTML"的便利，去动这 2,140 行的核心文件——风险收益完全倒挂。你花了很长时间调的东西，正好在这条路径上。

加页的正确做法：照现有结构加，别改机制

想加一个新页（比如"记忆详情"或"DSH 桥"），只需三处、约 50 行，不碰任何现有代码：

// ① ui/index.html —— 在「设置」前面插一个按钮（照抄现有 nav-item 的写法）
<button class="nav-item" data-top="ext" data-tab="memory-detail" title="...">
  <svg viewBox="0 0 24 24">...</svg>记忆
</button>

// ② ui/index.html —— 在对应位置插一个 section
<section data-tab="memory-detail" hidden> ...你的页面... </section>

// ③ 新建 ui/app/21-memory-detail.js，照 15-desktop-pet.js 的写法
//    在 11-init.js 里加一行 script 标签

这条路的好处：样式自动继承（同一套 CSS 变量和 class）、主题自动跟随、切换逻辑自动生效（data-tab 是现成机制）。而且随时可以删掉，不留痕迹。

所以"保留 0.4.9.1 的 UI"这件事，不但没冲突，反而让方案变简单了

砍掉 console.panels（300–500 行）和 ui.panels（800–1,500 行）之后，总改造量从约 2,000 行降到约 280 行，而且完全不碰 ui/ 目录。
