# 给洛版 0.5 的 bug 清单（我们这边实际踩到的）

> 环境：QQ Agent **0.4.9.0**（本地是 0.4.8.8 血统 + 我们自己的补丁），Windows 11，Electron 版。
> 说明：**只报核心（`src/` `electron/` `ui/`）与官方插件/skill 的问题**；
> 我们自研插件（toy-box / inner-life / her-world / daily-beats / pose-library …）的 bug 不算。
> 标「已本地修」的，是我们为了能用先打了补丁，**是否采纳由你们判断**，补丁位置写在后面方便对照。

---

## A. 编排 / 模型调用（最影响体验的三条）

### A1. 一轮完全空输出时直接 `noreply`，对方什么都收不到（已本地修）

- **现象**：某一轮 `completionTokens=175`，但 assistant 内容 0 字、`tool_calls` 为空 → 会话 `status=noreply`、
  面板显示「未回复 / 无文本输出」，群里的人什么都没收到。
- **证据**（本地会话 `mvpytymd-323ea41b`）：
  ```
  status: noreply · rounds: 1 · toolCalls: 0 · sent: []
  usage: promptTokens 36312, completionTokens 175
  messages: [ { role: 'assistant', content: '' } ]
  ```
- **根因**：`orchestrator.js` 在「没有工具调用」分支里，补一轮提醒的条件是
  `!unsentNudged && !session.sent.length && String(rawContent||'').trim()` ——
  **要求正文非空**。而这次正文本来就是空的，于是直接 `break`。
- **建议**：核心自己也兜一层：正文空 + 无 tool_calls → 补一轮
  「你刚才没有任何输出，要么 send_message，要么 finish 说明不说话」。
  替换模型/网关时这类空输出会变多，建议做成可配开关。

### A2. 推理型模型把 `max_tokens` 全花在思考上，正文为空（核心没有自动升额度）

- **现象**：识图/写文案时经常返回「模型没有返回正文」，但 `finishReason=length`。
- **证据**（同一批图 4 张，`max_tokens=1200`）：
  ```
  图1 → 空输出，finish=length，reasoning 1599 字
  图2 → 空输出，finish=length，reasoning 1588 字
  图3 → 空输出，finish=length，reasoning 2096 字
  图4 → 正常
  ```
- **根因**：`llm.js` / `chatCompletionWithRetry` 拿到「content 空 + finishReason=length」不重试。
- **建议**：核心在 `content 为空且 finishReason==='length'` 时自动**升额度重试一次**（或按模型配默认更高额度）。
  我们在插件里各自手写了 3 档阶梯，每个插件都得抄一遍，不该这样。

### A3. 官方 skill 把「动态提醒」写进 `promptSections()` → 击穿前缀缓存 + 自检告警刷屏

- **现象**：日志里 `[警告] 系统提示漂移 50 次 —— 最近变更的段落：自己的空间与资料`，
  一天（单份日志）出现 **206 条**。
- **根因**：`skills/qq-self/index.js` 的 `promptSections()` 除了静态策略段，
  还拼了一段「该发说说了」的提醒（依赖"距上次发说说的时长/今天配额"）——
  这段内容**每轮都可能变**，而 `promptSections` 属于系统提示（静态区）→ 前缀缓存每轮都失效。
- **建议**：核心提供/规范一个"易变内容"通道（追加到最后一条 user 消息，`before-llm-messages` 就是这么做的），
  并在 `promptSections` 的返回值上加 `volatile: true` 之类的标记，drift 检测直接跳过它们。
  否则：缓存命中率掉、自检告警把日志冲干净。

## B. 视觉 / 图片

### B1. `vision=true, video=false` 时 GIF 只给模型第一帧（已本地修）

- **现象**：她描述 GIF 表情包时"只看得到第一张"。现场：主人在群里发了个 3.85 秒动图，
  她回「整个人趴在地上往前一下一下地挪」——而第 4 帧（1.5 秒）其实是**凑到一碗白饭跟前**。
- **根因**：`src/tools.js` 的 `downloadImageAsDataUrl()` 在 `gif-image` 路线把 GIF 当**单个 image part** 发；
  模型侧只解码首帧。首帧是远景，后半段信息全丢。
- **建议**：核心在 `vision && !video` 时用随包 ffmpeg 抽 2~4 帧一起发（我们已经这么做了，
  `gifFrameDataUrls()`，3 帧约 150KB），或至少像 video 路线那样转 mp4 走视频模型。
  顺带：`collectImageResults()` 的"入库缓存优先"捷径也要走抽帧 —— 否则缓存过的 GIF 永远只有一帧（我们踩过）。

### B2. `get_message_images` 对「合并转发」消息返回"没有可查看的图片"（已本地修）

- **现象**：转发别人聊天记录（里面有多张图）→ 工具返回「消息 xxx 没有可查看的图片」。
- **根因**：核心 `get_message_images` 只认 `media` 里的图片段，不展开 forward 节点。
- **建议**：核心检测到 `[合并转发]`/`[转发消息]` 段时，自动展开 `read_forward` 再取图
  （我们在 `src/tools.js` 里加了这段委托）。

## C. 插件运行时（0.5 如果有插件体系，建议优先看这两条）

### C1. 热重载只给**入口**加 `?t=`，`lib/*.js` 仍命中模块缓存 → 假"加载失败"（已本地修/绕过）

- **现象**：给插件 `lib/` 里加一个新导出后 `POST /api/skills/reload`，报
  `The requested module './lib/toy-box.js' does not provide an export named 'slotLabelOf'`
  → 插件被判"加载失败（已保留旧版本）"，日志一条红字，看着像写错了代码。
- **根因**：`plugin-loader.js` 约 923 行 `await import(`${entryUrl}?t=${Date.now()}`)` —— 只 bust 了入口；
  入口 `import './lib/x.js'` 没有 query，模块缓存命中旧版。
- **建议**：要么给 `lib/` 也加 bust（可对入口做一次性改写），要么在 reload 时提示
  「本次只重载入口，`lib/*.js` 的改动需重启」。
- **附带**：热重载与"文件正在写"有竞态 —— 我们两次都是在编辑器保存的瞬间 reload，
  同样报上面那句。建议对写入事件做 debounce（几百毫秒）再 reload。

### C2. `createSkillApi` 没有 `tools` / `getTool`

- **现象**：插件想「枚举/调用宿主上的其他工具」（比如一个 skill 要复用核心的 `collect_sticker`）时，
  `api` 上没有任何入口 → 只能 `import('../../src/tool-registry.js')` 直连核心内部。
- **证据**：`src/harness/forge/gate.js` 的 `KNOWN_APIS` =
  `registerTool, config, isSkillActive, capability, hasCapability, storage, log, warn, error, fetch, utils`
  —— 没有 tools。
- **建议**：加 `api.tools`（列表）与 `api.getTool(name)`（调用），或 `api.callTool(name, ctx, args)`。
  直连 `src/tool-registry.js` 在打包/换布局后就断，属于隐患。

## D. 桌面端（Electron）

### D1. 桌宠右键菜单全部静默失效：`core.getDesktopPetService` 从未定义（已本地修）

- **现象**：桌宠右键菜单里 **隐藏桌宠 / 始终置顶 / 固定位置 / 鼠标穿透 / 视线跟随 / 看看当前屏幕**
  点了全都没反应，也没有任何报错日志。
- **根因**：`electron/main.js` 里 `getService: () => core?.getDesktopPetService?.() || null`，
  而 `src/app.js` 的返回值**没有这个方法**（0.4.9.0 的血统里有，我们这台 0.4.8.8 血统没有）→
  `service()` 恒为 `null` → `service()?.updateSettings?.(patch)` 静默不执行。
- **建议**：核心把 `getDesktopPetService` 纳入 `src/app.js` 的稳定导出（并在类型/文档里标明），
  或让 `electron/` 侧改为走 `POST /api/desktop-pet/settings` 兜底（我们也这么兜了）。

### D2. 桌宠菜单「强制还原」5 秒太短 → 菜单点不动（已本地修）

- **现象**：右键菜单弹出后，在主菜单上停留稍久，那些"临时取消置顶/鼠标穿透"的设置就被复位，
  表现为「菜单里点哪一项都没反应」。
- **建议**：兜底时间 5s → 30s（我们改了），或按 `menu-will-close` 事件而不是定时器来还原。

### D3. `core.getUsageToday` 缺失 → 用量卡片不可用（已本地修）

- **现象**：`electron/desktop-pet.js` 调 `getUsageToday()` 拿不到函数 → 用量卡片显示不可用。
- **建议**：同上，统一 core 对外导出的契约（或在 electron 侧做能力探测 + 明确提示）。

## E. 数据一致性 / 其他

### E1. 直接改 `data/stickers.json` 会被内存覆盖回去

- **现象**：脚本改了表情库文件，界面/她看到的还是旧值；更糟的是核心下次写盘会拿内存那份把磁盘盖回去。
- **根因（设计层面）**：有两个 `StickerManager`——核心 `src/sticker-manager.js`（`host.stickers` 用它）
  与官方插件 `plugins/sticker/lib/manager.js`。后者 `sync()` 每 60 秒
  `mergeStickerLibrary(内存, 远端)` 后 **`saveStickerStore(内存)` 整份写盘**，
  而且此时内存是"启动时的值 + 本次合并"。
- **建议**：单一写者（明确哪一份权威，另一方只读），或写盘前比对文件 mtime/内容指纹。
  现在改库必须走 `POST /api/config` 的 pending 通道，外部脚本/运维很容易踩。

### E2. `moodStateOf(key)` 传 chatKey 时**静默**返回默认值

- **现象**：`moodStateOf(chatKey)` 不报错，但心情永远是默认 60 —— 因为 key 实际是 `memoryKey`。
  我们一个插件因此把「自控」写成了常量，查了很久。
- **建议**：参数不是 memoryKey 形态时抛错或 warn 一次；文档里写明"不传 = 当前人格"。

### E3. `POST /api/*` 没有 `Origin` 头直接 403

- **现象**：`{"error":"请求来源不被信任（仅接受本机控制台的同源请求）"}`。
  当前窗口是 `http://127.0.0.1:3210/` 所以没事，但：
  插件自带 UI、或用 `file://` 加载页面、或本地脚本/自动化调用时，一律 403。
- **建议**：给本机进程加一个"控制台 token"（桌面端已有 `x-console-token` 的先例），
  或允许 `Origin: null` + 本机回环地址。

### E4. `[警告] 工具被排除：xxx（在扫描到的会话中出现 258 次）` 以 WARN 级刷屏

- **现象**：自检每次启动打一堆 `[警告] 工具被排除`（单份日志实测 **1472 条**，涉及
  `forward-relay__relay_send`、`body-shape__body_shape`、`sensitivity__*`、`toy-box__*` 等）。
- **说明**：这些是**插件按场景主动摘工具**（设计如此），不是故障。
- **建议**：这类"按设计被排除"的统计降成 `debug`，或聚合成一行摘要；
  真正异常（工具注册冲突、能力缺失）才用 WARN。
