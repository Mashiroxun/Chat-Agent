1. cache-guard · 前缀缓存哨兵 插件默认启用

解决什么：命中率 93.36% 意味着每天约 75 万 prompt token 未命中缓存，而任何插件改动系统提示都会悄悄击穿前缀——此前毫无线索。
怎么工作：① 每次调用从 session.lastCallCache 聚合每日/每群的命中率（含单次最低/最高）；② 对系统提示按 ▸ 小节 切段做指纹，任何段落漂移立即告警并归因到具体段落（如「分层会话记忆」改了它的片段）；③ 注册 cache_report 工具，问"缓存怎么样"时模型可自查。
红线遵守：数据只写 data/plugin-data/cache-guard/（节流 30s + tmp/rename 原子写），绝不写进 plugins/ 触发热重载风暴。

2. anti-flood · 刷屏话题锚点 插件默认启用

两级裁剪（全规则、不走 LLM）：
L1 对象级：before-context 把同一发送者 3 秒内的连发合并为一条（保留首条消息 id 作回复锚点，文本以「 ／ 」拼接）。
L2 文本级：历史块里同一发送者的连续占位符行 [图片][图片][图片] 折叠成 [图片×N]（保留首行 #id）。
锚点保护：带 @、带引用、带媒体、自己发的消息永不合并；【本次唤醒】块的行永远不折叠——回复锚点（replyToMessageId）永远有效。
真实数据实测（诚实版）：
指标实测
L1 连发合并（153 个带 trigger 的会话）合并 225 条，trigger 字符节省 5.2%
L2 历史占位符折叠（40 个会话样本）节省 0.2%——该群虽 1 秒/条但轮流发图，同发送者连续段最长只有 2 连，故默认 foldMinRun 已调为 2
结论：价值主要是 L1 的节流 + 减少 anchor 噪声，量级比初版计划估计（25~40%）小得多——以实测为准。

3. presence · 参与度自适应 插件默认关闭

针对：机器人发言占全群 22.5%（581/2584），且 363 个会话里只有 6.9% 主动选择不说话。
三层介入：① 账本——每群维护最近 120 条的 (ts, self) 滚动序列（纯内存）；② 软介入——占比 ≥25% 时在系统提示注入「这轮倾向安静」建议（动态片段，不报数字）；③ 硬介入——占比 ≥32% 且 8 秒内刚发过言时，before-tool 直接否决 send_message（模型收到工具错误自然收尾，不烧额外 API）。
逃生门：带 replyToMessageId 或带 @ 的发送放行（可能是被点名）；否决冷却 60s 防死循环。冒烟测试已验证：25% 软介入、32.5% 硬否决、引用放行、@放行、冷却全部符合预期。

4. relationship · 关系状态 插件默认关闭

机制来源：health-system 证明了「状态只改语气、绝不显示数值」是让模拟角色自然的关键——本插件把同一机制搬到群友关系上。
怎么工作：每个群友一个 0~100 隐藏熟悉度（说话 +1.2、含 @ +2.5、引用 +3、每天衰减 1.5）；动态片段向系统提示注入自然语言关系描述：「老熟人可以开玩笑/接梗」「常打照面语气放松」「新面孔礼貌克制」，本次唤醒里在场的人优先描述。
保密指令：片段末尾硬性要求「绝不要在聊天里提熟悉度/好感度或任何数字」。状态落 data/plugin-data/relationship/，热重载不丢。

5 + 6. topic-tracker / group-profile 技能默认关闭

两个 LLM 技能补「模型几乎不主动翻历史」的行为缺口（363 个会话里 get_recent_messages 只被调过 3 次）。检索本身是纯确定性统计，零 LLM 成本：
· topic-tracker：topic_timeline 把某天消息按 8 分钟间隙切段（时间段/参与者/关键词/例句）；topic_search 按关键词跨天回搜。已用真实存档验证：2584 条切成 3 段、「鲸鱼」30 天回搜 21+ 条命中。
· group-profile：group_profile 出排行榜/单成员画像/时段分布（含机器人占比提示）；daily_digest 按小时分块的流水摘要。已用真实存档验证全部三个工具。

启用指南

  1. 应用启动后热重载自动加载两个默认启用的插件（cache-guard / anti-flood），启动日志可见「✅ 加载成功」。
  2. presence / relationship / topic-tracker / group-profile 到「技能管理」里手动打开；开关只有一处 config.skills[id].enabled。
  3. cache-guard 跑一天后对机器人说「缓存命中率怎么样」即可拿到报表；系统提示一旦被谁改了，漂移记录会直接点名段落。
  4. 所有插件可在设置界面按 configSchema 的中文标签调参（阈值/窗口/开关）。
