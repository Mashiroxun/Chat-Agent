QQ Agent v0.4.8.9 发布说明

v0.4.8.9 ← v0.4.8.8 · 2026-10-22
稳定性版 群禁言全链路修复 表情包引导强化

这一版解决两个「功能都在、但就是不生效」的问题：被禁言后机器人还在空转烧 token， 以及机器人几乎不发表情包。前者是三个集成点只接了一个，后者是省 token 机制把表情的 轮次吃掉了 —— 两件事的共同点都是「代码看着对，行为对不上」。

一、修复

修复群禁言「禁言后不说话」：七个断点全部接上
实测禁言 10 分钟：连跑 4 个会话、净烧约 19.5 万 prompt token、5 次发送全部被拒 （result=120）、0 条消息送达。根因是「零件齐全、装配缺失」——事件写入端 从未接线，唯一的查询兜底又被 60 秒缓存架空，而所有失败路径都是静默的。
  • 缓存穿透：ban-state 新增状态变化订阅，禁言 / 解禁 / 到期三条路径都直接覆写缓存，不等 TTL。
  • 协议层接线：group_ban 事件只认 user_id === self_id（群友被禁言不能把自己标成禁言），ban+duration>0 → 禁言中，lift_ban → 解除。
  • 发送层兜底：识别 result=120 签名 → 立即标记禁言 + WARN；全败时抛出带 muteRejection 的结构化错误。
  • 终态化：send_message 把禁言失败作为终态返回给模型（「已被禁言，请勿重试」），实测掐断了把单请求 body 撑到 1.9MB 的重试风暴。
  • 开关接线：skipRunWhenMuted / markReadWhenMuted 以前算了没人读，现在真的生效。
  • 可观测性：跳过路径记 INFO（群、剩余秒数、依据、标已读条数）；查询失败 / selfId 缺失补 WARN，排障时能区分「没被禁言」和「查不到」。
  • 提醒闸：禁言期到点的提醒延后补发，不再 20 秒一次刷屏报错。
修复表情包发得少：从「模型性格问题」改到机制上
实测机器人发表情率 3.2%（10 次 / 315 条发言），不到群友带图率（7.6%）的一半； 149 条 ≤10 字的短反应全是纯文字。根因不是模型不想发，而是 10-01 上线的「发言即收尾」 （autoEndAfterSend）把「先说文字、下一轮补表情」这条路物理斩断 —— 纯文字批发完会话就结束，表情排在下一个不存在的轮次里。
  • P1短回应硬指引：策略段新增一行 —— ≤10 字的纯反应优先配图，且必须与 send_message 同批调用；仅在有效档位 ≥2 时出现（0/1 档是你明确要「少发」）。
  • P2主动收藏：从「你开口说收藏它才收」改成「看到合适的图就收」，看图确认降级为可选步骤；note/tags/usage 三件套与每小时 10 次的上限不变。库容过 10 张后档位自动解锁。
  • P3收尾精细化：本该立刻收尾时先问一次 —— 满足「短回应或刚有人发图 + 库里有图 + 档位 ≥2 + 5 分钟冷却 + 本次唤醒未宽限过」才多给一轮，在 tool 结果之后补一条提醒。其余情况照旧立刻收尾。

成本：每宽限一次多跑一轮，约 19K token，所以卡在「短回应 + 5 分钟一次」。 想彻底关掉：配置里把 api.autoEndStickerGrace 设为 false 即可退回旧行为。

修复内置模块基线与磁盘不一致（重启会拒载 ban-state）
改完插件代码后没有重算 builtin-modules.json，ban-state 的指纹对不上 → 下次启动时信任闸会把整个模块判为「占名顶替」，禁言功能会静默失效。本次已重算， 打包前也复核了 24 个内置模块的逐文件指纹全部一致。
清理旧表情模块下线（581 行死代码）
src/stickers.js / src/sticker-manager.js 里还留着一份旧的策略提示， 文案仍在教模型「先发文字、再单独发表情」—— 与 10-21 的修复直接矛盾，留着就是下一个坑。 全仓检索确认无人引用后删除（备份保留在开发侧，不随包分发）。

二、升级须知

  • 建议重启：内置模块的信任基线带 mtime 校验，基线文件变化时热重载会重新读盘；重启仍是最稳妥的确认方式。
  • 覆盖安装即可：本包不含 data/（你的配置、会话存档、记忆、表情库、密钥都在那里）， 装到新目录或覆盖旧目录都不会动它们。
  • 首次启动会自己建 data/：全新安装需要重新填 API Key、重新登录 QQ。
  • 本次新增两个内部开关（默认都是「开」，不配也能用）：api.autoEndStickerGrace（收尾宽限）、 api.autoEndAfterSend（发言即收尾，老开关）。
  • 验收观察点：日志里 收尾宽限一轮 的频率（正常一天几十次，不是上百次）； 一周后看 stickers.json 的 useCount 有没有从 3.2% 往 6% 走。

★ 打包时必须排除的

下面每一项都是明文凭据或隐私，漏一项就等于把密钥和群聊记录一起发出去。 make-zip.mjs 已把这份清单写成代码里的底线（命令行只能追加、不能替换）， 并且打包前还会按特征再扫一遍，命中就中止。

排除路径里面是什么
data运行时数据根：API Key（config.json）、全部群聊记录（sessions）、记忆、usage、表情库
resources/app/data同一份运行时数据的另一处落点（开发/直跑模式会用这条），本次新增排除
.workbuddy开发工具数据：调试脚本、笔记、备份
dev-sandbox开发工单沙箱（运行时产物）
resources/app/snowluma/dataQQ 消息库（约 39MB）、媒体库、身份库及 WAL
resources/app/snowluma/logsSnowLuma 运行日志
resources/app/snowluma/configOneBot access token、WebUI 密码哈希与盐（整个目录排除，换 QQ 号也不会漏）
*_归档-发布前清理历史上的清理备份目录

必须保留：LICENSES.chromium.html、LICENSE.electron.txt —— Chromium / Electron 的许可证，法律要求随包分发。
