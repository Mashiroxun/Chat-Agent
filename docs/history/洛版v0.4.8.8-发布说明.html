一、新增

harness 四模块内置化 架构
系统自检（self-doctor）、自动修复（self-fix）、扩展锻造（extension-forge）、开发工单（dev-orders）从 plugins/ 迁入 src/harness/，以 kind=core 注入。它们不再出现在"插件"页、不会被误禁用、也不会被"磁盘已删除"逻辑误卸载。 代价：这四个模块改完不再热重载，需重启生效。
表情策略：容量档 + 同批发送 体验
发表情频率改为 min(配置档, 容量档)：0 张不再承诺、1–3 张 1 档、4–9 张 2 档、≥10 张回到配置档； 提示词改为"文字与表情放在同一次调用里发"，避免被自动收尾逻辑砍掉第二句。
收藏表情支持标签与适用场景 体验
collect_sticker 新增 tags（数组或逗号串）与 usage（一句话场景），候选列表直接渲染 [tags]，挑选更准。
身份锚点与 @ 判定 体验
系统提示里的"我是谁"改为「群名片 / QQ 号 / 角色名」三件套（名片自动带 10 分钟缓存）； 每条被 @ 的唤醒消息会在提示词里注入一行「这一条 @ 了你本人」，被点名不再静默。

二、修复

自动修复工单"改到闸门可通过、闸门却不放行" P0
批准令牌原来只消费不重置：apply 失败或回滚后再申请必然 403，而 commit 又要求 verified —— 工单直接死透。 现在：提案带指纹（改动即失效并提示）、verify 失败 / rollback 后自动换票退回 proposed、暂存区保留可 rerun。
视频抽帧找不到随包 ffmpeg P1
findFfmpeg() 原先只查 PATH，导致"包里明明有 ffmpeg、插件却报未找到"。 现在先解析随包的 resources/app/runtime/ffmpeg.exe，再退回 PATH。
密钥端点仅靠 Origin 同源保护 P1 · 安全
伪造 Origin 头即可读到明文 WebUI 密码。现在密钥类端点一律要求 server.allowBrowserKeyRead 显式开启（默认 false）， 实测无凭据 / 伪造同源 / 跨源三种来源全部 403，/api/config 里的 apiKey 也已脱敏。
语音模块把提示词击穿缓存 P1 · 性能
speech-to-text 的 available() 在探测中乐观放行，配合"失败 60 秒后重探"造成状态来回翻转， 系统提示的「语音消息」段每 60 秒增删一次 —— 实测贡献当日约 28% 的缓存 miss。改为探测中返回不可用。
语音模块改完后被安全闸拒载 P0 · 本次修
改了 plugins/speech-to-text/index.js 却没重算 builtin-modules.json， 基线判定"内容与随包不一致"→ 整个模块被拒载（现象是功能静默消失，不报错）。本版已重算基线，24/24 模块全部加载成功。
接口语义：错误码该 4xx 的不再报 5xx P2
/api/models 空配置 → 400（原 502）；persona 非法 id → 400、不存在 → 404（原 502）。
QQ 拒发不进用量账本 P2
发送失败现在会透传到 usage 的 errors 计数（按调用计数），不再只有协议端日志里能看到。

三、升级须知

  1. 需要重新登录与配置：data/ 不在发布包内（含 API Key、群聊记录、记忆），收包人首次启动要重新登录 QQ 并重填配置。
  2. 改内置模块必须重算基线：动过 plugins/ 或 skills/ 后，执行 node .workbuddy/tools/refresh-builtin-baseline.mjs，否则收包人侧该模块会被准入闸拦下（表现为功能静默消失）。
  3. harness 四模块不再热重载，改完要重启应用；它们也不在"插件"页显示，自动修复开关在「工具 → 自检 → 自动修复」。
  4. 语音转文字需要填 modelPath：未填时模块正常降级为不可用（提示"还没填模型文件路径"），不再是时好时坏。
  5. 文生图 / 账号池 / 主人 QQ 三项仍未配置时，对应能力会显示明确原因并降级，不影响其余功能。
  6. 建议覆盖升级前先备份自己的 data/（配置、记忆、聊天记录、登录态都在里面）。

五、软件内的「更新报告」也更新了

软件首页（会话首页底部）那张「更新报告」卡片读的是本地数据，不接线上检查，离线也看得见。本次把 0.4.8.8 这一条从 11 项扩充到 24 项，把 10-21 的记忆检索 / 安装包修复与之后两天的改动全部并入、统一改写成口语化描述：

  • 体验：被 @ 不再装没听见（身份锚点三件套 + @ 判定行、finish 拦截后真的再走一轮）、发表情改成同批发送、频率按库存自适应、收藏支持标签与用途；
  • 工程：自动修复工单不再"改到一半死透"、四个开发类工具内置化（不再出现在插件列表、改完需重启）、自动修复开关有了入口、左栏「工具」二级页签名改回 harness；
  • 稳定：视频抽帧认随包的 ffmpeg、语音消息不再时好时坏（探测期一律不可用，不再击穿缓存）；
  • 安全与语义：密钥端点伪造同源一律 403、502 改 400/404、被 QQ 拒发的消息记进用量账本。
维护约定（写给后续维护者）：这张卡片按版本号记住"已关闭"—— 只有 STAGE_CHANGELOG 第 1 条的 version 换新号，关掉过的用户才会再看到一次；只改 items 不动 version，他们不会再看到。 本次用户明确要求并入 0.4.8.8（不另起新号），因此 version 未动、date 同步为 2026-10-22 —— 已关过这一版的人不会自动再看到，知情即可。
