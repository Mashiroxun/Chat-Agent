## 症状

用户反馈：「手动展开的为什么会自动收起」——点开一张卡来读，没过多久它自己合上了。

## 两条自动收起的路径

1. **新会话到达 → 自动跟随切选中 → 全量重建**：`autoFollowRunning` 默认 true，新会话一来 `selectSession(新id)`，重建时 `applyRightInner` 把**所有非选中卡**一律 `collapsed` 并收掉卡体——用户正在读的那张卡被连带收起（内容也没了）。
2. **会话跑完 → `autoFoldTick` 按 r37 设计自动收起**：`active → over` 迁移时无条件 `classList.add('collapsed')`。用户手动展开着一张正在运行的卡，会话结束时被合上。

另有两条同源分支（包裹层 `madeBody` 的"别的卡收起"、R117 点击处理）也会在特定时机波及。

## 修复：用户手动展开 = 特权状态（`ccUserExpanded` 账本）

模块级 `ccUserExpanded {sid → true}`，**只有用户能开关**：

| 操作 | 账本 |
|---|---|
| 点开折叠卡 | 记账（同时手风琴收起别的卡 → 那些卡销账） |
| 点已展开卡头（手动收起） | 销账 |
| 自动跟随 / 轮询重建 / 状态迁移 | **无权改动** |

四处路径全部绕开被记账的卡：
1. `applyRightInner` 重建前：把"用户展开且非选中"的卡体摘进离帧容器 `ccBodyHold`（刻意不用 HOLD——`collectSessionNodes` 会扫 HOLD 造成错挂），重建后原样挂回 + 保持展开；不在新列表里的会话销账。
2. `autoFoldTick` 活跃→终态：`ccUserExpanded` 里的卡不自动收起。
3. 包裹层 `madeBody` 分支收起"别的卡"时：跳过被记账的卡。
4. 点击处理：手风琴语义确定化（原来只在新建卡体时才收别的卡，点多张已看过的卡时状态不确定；现在一律收，被收的销账）。

重建后的滚动锚定（R118/R119）顺序不变——卡体挂回放在 `autoFoldTick` 之后、`restoreScrollAnchor` 之前，高度差计入补偿。

## 语义核对

| 场景 | 行为 |
|---|---|
| 用户展开卡 X，新会话自动跟随 | X 保持展开 + 内容不丢；新会话卡在顶部展开 |
| 用户展开运行中的卡，会话结束 | X 保持展开（不自动收） |
| 用户手动收起 X | 立即收起 + 销账，之后一切自动行为恢复对该卡的管辖权 |
| 用户点开另一张卡 Y | 手风琴：X 收起销账，Y 展开记账 |
| 会话被清理/删除 | 卡体不存在 → 不挂回，账自动销 |
