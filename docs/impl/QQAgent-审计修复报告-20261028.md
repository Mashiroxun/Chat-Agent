## 一、高危（3/3 已修）

### H1 安全闸正则可被 `module.require('fs')` 绕过

- 位置：`src/harness/forge/gate.js:77`、`src/harness/fix/checks.js:46`（双副本同步改）
- 根因：锚点 `(?:^|[^\w$.])` 把 `.` 排除在外，`module.require('fs')` / `globalThis.require('net')` / `process.mainModule.require('fs')` 全部匹配不到。
- 修法：锚点改为 `(?:^|[^\w$])`（不再放过属性访问式取模块）；require 分支放宽为 `require\s*\)?\s*\(\s*`，覆盖 `(require)('fs')`。

### H2 第三方 zip 套用模型草稿限额，大扩展被静默截断

- 位置：`src/harness/forge/forge-tools.js`
- 根因：`extractZipToDraft` 用 `DEFAULT_LIMITS`（256KB/文件、1MB/总体积），超限 `skipped.push` 后 `break`，闸门照常放行。
- 修法：
  - 新增 `ZIP_LIMITS`（16MB/文件、128MB/整包）与 `ZIP_MAX_BYTES`（parseZip 前的包体上限），与写盘限额彻底分离。
  - 改为「先规划、后写盘」：体积校验通过后才落盘；**超限整包拒绝**（`ok:false` + 明确文案），不再跳过。
- 回归：1.8MB 三文件包完整解出；20MB 单文件整包拒绝；超总体积整包拒绝；正常小包照常通过。

### 第 10 条（forge 超时预算）：复核后不成立

原报告称"后端最坏 8 轮 × 240s ≈ 2400s"。实际读码：`runDraftLoop` / `runLoop` 的 240s 定时器是**整个循环共享一个 AbortController**，8 轮不是各自 240s。真实最坏预算：

- 起草：计划 30s + 起草 240s + 自动修复 2×240s = **750s**，前端给 820s；
- 升级：首轮 240s + 2×240s = **720s**，前端给 780s；
- 适配：2 段 × 240s + 前后置闸门 ≈ **500s**，前端给 620s。

三层都在前端预算之内。但复核发现另一个**真实且独立**的问题：客户端超时断开后，后端 handler 不监听 `req.close`，任务会继续跑完 —— 这属于"取消传播"缺失，改动面覆盖 routes 里所有长任务，建议单独立项，本次未动。

### 明确未改（需单独评审）

- **cache 检查只看最近 1 天**：改成多天会改变告警语义（同一条漂移连报 N 天），应先设计"最近 N 天聚合"再动。
- **scan.js Promise 检测链尾 `)` 误判**：属误报类，需重写检测器而非调参。
- **fix 回滚覆盖提交后的人工改动**：需要在 commit 时记录落地后指纹、回滚前比对，是行为变更。
- **暂存草稿不自动清理**：草稿是用户资产，自动删风险高；本次只给"备份"加了保留策略，草稿建议加手动清理入口。
