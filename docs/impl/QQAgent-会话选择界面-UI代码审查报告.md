# QQAgent 会话选择界面 UI 代码审查报告（15-chat-chrome.js 及其交互面）

- 日期：2026-10-14
- 审查范围：`ui/app/15-chat-chrome.js`（全文 1340 行）+ `02-sse-sessions.js` 交互点 + `style.css` 相关规则
- 审查方式：通读 + 状态机清点 + 逐路径走查（不动代码）
- 结论先行：**当前没有语法/运行时错误，逻辑自洽；但 R114~R121 的十一轮补丁已全部压在「右栏全量重建」这一个根因上，补丁塔到了极限。建议做一次针对性重构（本条 + P0-2 + P1-4），而不是继续打补丁。**

## 一、状态机清点（为什么这个文件越来越难改）

这个文件里同时存在 **10 套状态/缓存机制**，互相制衡：

| 机制 | 行 | 职责 |
|---|---|---|
| `ccPendingExpand` | 53 | selectSession 后强制展开（实际对所有调用方生效，不止用户点击） |
| `ccUserExpanded` | 59 | R121：用户手动展开账本 |
| `ccBodyHold`/`keepBodies` | 62/836 | R121：重建时暂存被展开卡体 |
| `ccAnchor`/`ccLastChat` | 86/68 | R118/R119：滚动锚点（5s TTL、3 入口） |
| `snaps` | 1222 | R114/R120：详情包裹层滚动快照 |
| `runSeen` | 1038 | r37：运行态迁移账本 |
| `data-head` 签名 | 870 | R115：卡头刷新守卫 |
| `HOLD`/`borrowed` | 549/550 | 离屏暂存 + 借出面板追踪 |
| `warned` | 646 | applyRight 报错只 warn 一次 |
| `st.chat`/`st.q` | 49 | 本层选中聊天/搜索词 |

单个看每个都有注释、有理由；合在一起的结果是：**任何一次 SSE 事件要穿过 3 层包裹（renderSessionList / renderSessionDetail / selectSession）、4 个账本、2 个暂存容器**。本轮用户报的每个 bug（展开延迟、跳顶、自动收起）都是这套机器的输出，不是独立故障。

## 二、发现的问题（按严重度）

### P0-1（架构根因）右栏每次新会话都全量拆建

`applyRightInner`（798 行起）：`DETAIL.innerHTML = ''` → 重建 N 张卡 → 重绑点击 → 挂回卡体。触发者包括最常见的**新会话自动跟随**（02 `session-start` → `selectSession(新id)` → 详情包裹层回退分支 1204 行 → `applyRight(true)`）。

后果（全部已复现过）：滚动归零（R118/R119 治）、展开态丢失（R121 治）、卡头重绘、事件重绑、每几秒一次的全量 DOM 翻转（活跃群里）。**R118~R121 四轮补丁都是在阻止这次重建的副作用，而不是消除重建本身。**

左栏在 R114 已换成增量 reconcile（节点复用 + insertBefore + 指纹比对），被验证稳定；右栏没有。

### P0-2 新会话卡只在全量重建时才出现（右栏列表可能缺最新会话）

`refreshCards`（1007 行）只更新**已有卡**的卡头，不建卡；`fillLeft` 只管左栏。右栏 `#cc-cards` 里新增会话的唯一入口是全量重建（P0-1 的触发者）。而自动跟随**只在“存在 waiting/running 会话”时才触发**（02 第 27 行）——开始即结束的短会话、或用户正读着旧卡时自动跟随把选择切走后结束的会话，**在右栏里根本不出现**，直到某次切聊天/切页/慢接口兜底才补上。左栏计数和右栏卡片数不一致。

### P1-3 慢接口路径会丢用户展开态（R121 的实际漏洞）

02 的 `selectSession` 带 200ms 延迟占位（`detail.innerHTML = '加载中…'`，02:665）：大会话拉取超过 200ms 时，**占位会把整个 #cc-cards 连 R121 暂存外面挂着的展开卡体一起销毁**。此时 `ccBodyHold` 已被上次重建排空 → settle 兜底重建时 `keepBodies` 快照相不到东西 → `ccUserExpanded` 里的卡变成「账在卡亡」：折叠、无卡体、内容永久丢失，只能靠用户再点一次自愈。**这条路径今天就能触发（本机 227s 大会话 + 繁忙群）。**

### P1-4 自动跟随在“抢”用户的选择

`autoFollowRunning` 默认 true（00-core.js:279）：每个新会话都把 `state.currentSessionId` 切到它。用户正在读旧卡时，左栏高亮跳、当前会话变、选区内容被换。R121 只保住了展开态，**“被抢”本身没解决**——这是用户体感“还是有bug”的来源之一。

### P2-5 滚动锚点 5 秒 TTL 偏短

`restoreScrollAnchor` 丢弃 5 秒前的锚点。慢机器/大会话的详情拉取超过 5s → 锚点过期 → 跳顶复发。聊天守卫（`a.chat !== st.chat`）已经在防“陈旧锚点错位”，TTL 放宽到 30s 风险可控。

### P2-6 同一次事件跑两遍 fillLeft

自动跟随路径：`renderSessionList` 包裹层跑一次 fillLeft（1175 行），`applyRightInner` 末尾再跑一次（963 行）。每次都全量 `chatGroups()` + 全量 reconcile。`st.chat` 没变时第二次可以跳过。

### P2-7 `sessionsOf` 反复全量排序

`applyRightInner`/`refreshCards`/`autoFoldTick`/`chatGroups` 每次调用都 `filter + sort` 整个 sessions 数组（本机 4100+ 会话）。一次 SSE 事件算 4~6 遍。可加 1s TTL 缓存（R113 同款套路）。

### P2-8 02 去重时 autoFoldTick 不跑

包裹层把 `autoFoldTick()` 放在 `if (fresh.length)` 里（1269 行）：02 指纹未变提前返回时，运行→终态的自动收起/展开检测跳过，要等下一次事件才补。

### P2-9 `warned` 让 applyRight 错误只现声一次

646 行：第一次之后静默。后续同类错误表现和“功能没写”一样，误导排查（r25 的教训反被这个 flag 重新引入）。

### P2-10 手风琴直接销毁其他卡卡体

R121 点击处理（946 行）：`b2.remove()` 把别的展开卡卡体**销毁**。CSS 本来就是 `.collapsed .bs-cb { display:none }`——摘出暂存即可，不必销毁；销毁还放大了 P1-3 的内容丢失面。

## 四、建议路线

**A. 根治（推荐，工作量中等）**：右栏照左栏的 R114 方案做**增量卡片 reconcile**——卡节点按 sid 复用、新会话卡 `insertBefore` 插顶、卡头就地更新、选中/展开态按 class 切换，卡体节点不销毁。这一项同时消掉 P0-1/P0-2/P2-6，R118/R119/R120/R121 四组补丁可大部分退役（代码净减少）。
**B. 配套（小）**：自动跟随加“用户接管”暂停——用户手动选中某会话后 60 秒内（或直到该会话终态）不接受系统自动切换选择（治 P1-4，用户体感最直接）。
**C. 补漏（小）**：P1-3 的孤儿卡体回收（selectSession 入口②预摘非选中展开卡体，带 sid 标记，重建时回收）；P2-5 TTL 放宽；P2-8 把 autoFoldTick 移出 `fresh.length` 门。

建议顺序：**B → C → A**（B/C 各几十行、当天可验证；A 一次做完右栏 reconcile，之后这类"滚动/展开"bug 从源头不再发生）。

> 本报告只做审查，未改任何代码。确认路线后我按 B/C 先行实施，A 排期单独做。
