## 一、改造前长什么样

截图 `conn-改造前.png`（1440×900 真实渲染）。当时一屏之内有：

| 区块 | 里面有什么 |
|---|---|
| 页头 | 标题 + 状态徽标 + 重新检测 |
| 现在的状态 | 结论卡 + 3 条事实 + 诊断详情折叠 |
| 装一个协议端 | 两张卡（SnowLuma / NapCat），各带「打开」「复制」两个按钮 |
| 协议端进程 | 目录 + 自动查找 + 启动 + 停止 + 自动启动 + 日志面板 + 打开控制台 + 刷新 |
| 一键接入 | 阶段说明 + 密码框 + 接入 + 重新检测 + 一大段合规说明 |
| 端点设置 | 4 个输入框 + 4 个按钮 |
| 应用日志 | 日志面板 + 等级下拉 + 刷新 |

**10 个按钮、8 个区块**，而且「装协议端 / 协议端进程 / 一键接入」其实是同一条线上的三步，
却被平铺成三块并列，谁也不告诉用户"现在该点哪个"。

更糟的是：**已经连上之后，整套接入向导还在**，绿色"已经接入了"和上面绿色"机器人工作中"
说了两遍同样的事。

## 三、设计原则

1. **一屏只回答两个问题**：现在什么状态、我下一步点哪。
2. **渐进披露**：当前步展开，其他步收成一行；连上之后引导整块消失。
3. **老功能一个不删**：端点/令牌、自动读取配置、协议端日志、应用日志、诊断复制
   全部保留，只是默认折叠 —— 老用户展开就能用，新用户不会被吓到。
4. **步骤 ② 的"完成"只认 OneBot 真连上**，不认"注入成功"。注入完到 OneBot 起来有
   1~5 秒，那几秒画成绿色会让人以为已经能用，然后在群里发现没反应。

## 四、实现

- `ui/app/03-connection.js`
  - 新增 `connGuide()`（纯函数，算两步状态与当前步）与 `connStepsHtml()`（步骤条）；
  - 重写 `renderConnectionPage()`：状态卡 → 条件渲染引导 → 四个折叠；
  - `renderOnboardBlock()` 外壳从 `.sl-section` 改成 `.conn-step-card`（步骤 ② 的卡片）；
  - `connApplyProc()` 兼容两个停止入口（步骤 ① 卡片内 / 折叠区内）；
  - 步骤 ② 完成判定：`connected`（不是 `stage==='ready'`）。
- `ui/style.css`：新增 `.conn-steps / .conn-step-card / .conn-step-* / .conn-alt / .conn-adv-sub`。
  结论卡沿用原有 `.conn-verdict` 类名，配色与动效零改动。

## 五、怎么验证的

用 Edge headless + CDP 截的真实页面（不是拼图）：

1. `Emulation.setDeviceMetricsOverride 1440×900` —— ⚠️ headless 默认视口只有 ~464px，
   不设这个会截成"布局崩了"的假象（第一次就踩到了）；
2. 打开 `http://127.0.0.1:3210`，`switchTab('connection')`；
3. 已连接态直接截；
4. 未连接的两态用 CDP 注入模拟（改 `/api/status` 响应 + 设 `connOnboardCache`），
   避免为了看效果真去停协议端。
