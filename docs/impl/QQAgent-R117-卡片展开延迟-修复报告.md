## 症状

用户截图：一条已中止的终态会话卡（`16:57:28 · 0 轮 · 用时 227.8s` + 「中止」pill），折叠态。反馈「点击下拉（卡头）感觉会延迟一会才弹出来」。

## 根因

R116 把「必展开」的保证放在了 `renderSessionDetail` 包裹层里——而包裹层要等 **`/api/sessions/:id` 拉取完成 + 详情渲染完成**之后才执行（终态会话走 `sessions.get()` 读盘 JSON，运行中走内存 `structuredClone`，加上网络与渲染，几百毫秒起）。在这整段时间里卡片保持折叠 → 用户感知为「点了愣一会才弹出来」。

展开是**纯选择语义**（用户点了哪张卡），根本不该排在数据加载后面。

## 修复（两处）

1. **卡头点击处理改同步展开**：点下去立刻 `remove('collapsed')`；没有卡体就顺手建一个带「加载中…」占位的空 `.bs-cb`（展开立刻有内容区，同时保持「别的卡收回卡体并折叠」的新选中态语义）。内容随后由包裹层的 `wantExpand`/`fresh` 分支填入，两侧不冲突。
2. **手动收起即取消待展开意图**：`else` 分支里 `ccPendingExpand = null`——消除「连点两下（展开→立刻收起）时，晚到的详情渲染凭 ccPendingExpand 把卡又抢开」的竞态。
3. **附带加固**：`selectSession` 包裹层在 promise 落地后（then/catch）再查一次 `#cc-cards` 骨架，缺失则 `applyRight(true)` 重建。覆盖两条既有裸露路径：详情 >200ms 时 02 的延迟占位（`hintTimer`）把骨架写花、接口失败时 02 直写「加载失败」——此前慢接口/失败后右栏会停在裸文本状态。

## 语义核对

| 场景 | 行为 |
|---|---|
| 点折叠卡头 | 立刻展开（同步）+ 占位盒 → 内容到达后填入 ✅ |
| 点已展开卡头 | 只收起；同时取消该卡待展开意图 ✅ |
| 慢接口（>200ms） | 卡片已展开；接口落地后内容填入；骨架丢失会重建 ✅ |
| 接口失败 | 卡片保持展开态；骨架丢失由兜底重建（不再停在裸「加载失败」） ✅ |
| 轮询/SSE 刷新 | 不经点击路径，折叠态仍被尊重 ✅ |
